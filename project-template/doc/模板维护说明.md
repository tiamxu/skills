# 模板维护说明

## 一、维护对象

```text
project-template/AGENTS.md
project-template/CLAUDE.md
project-template/doc/项目开发规范.md
project-template/README.md
kit/
```

## 二、职责边界

- `project-template`：规范源头，维护通用执行规范和开发规范
- `kit`：基础代码库，提供 `kit/log`、`kit/http`、`kit/sql` 和项目生成能力

## 三、更新顺序

`kit` API 变化时，按以下顺序更新：

1. 确认 `kit` 最新用法
2. 更新 `project-template/AGENTS.md`
3. 更新 `project-template/CLAUDE.md`
4. 更新 `project-template/doc/项目开发规范.md`
5. 新建空目录试跑 `kit` 项目生成工具
6. 执行 `go mod tidy`
7. 执行 `go test ./...`

## 四、检查项

- `AGENTS.md` 与 `CLAUDE.md` 是否冲突
- `CLAUDE.md` 是否只作为入口，不重复维护完整规范
- `doc/项目开发规范.md` 是否同步最新规则
- `kit` 项目生成工具生成的代码是否使用最新 `kit` API
- 是否仍使用旧路由、旧启动方式或旧依赖
- 是否存在真实密钥、数据库密码、Token、第三方私密配置
- 是否新增了未经确认的依赖或技术栈
- 是否破坏 `api -> service -> repo -> model` 分层

## 五、版本规则

```text
v0.1.x  文档小修
v0.2.x  规范调整
v1.0.0  稳定可长期复用
```

版本变更时同步更新 `README.md` 顶部版本信息。

## 六、新项目验证流程

在空目录中执行初始化后检查：

```text
AGENTS.md
CLAUDE.md
doc/项目开发规范.md
api/common.go
config/config.go
repo/init.go
routes/routes.go
main.go
```

然后执行：

```bash
go mod tidy
go test ./...
```

初始化结果必须满足：

- 可编译
- 无真实密钥
- 使用 `kit/log`、`kit/http`、`kit/sql`
- 使用 `kithttp.NewServer`
- 注册路由后调用 `srv.Start()`
- SQL 只出现在 `repo/`
